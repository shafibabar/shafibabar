How I Build

The discipline behind the builds

I direct AI-assisted builds the way I run product: a written charter, decisions on record, tests before code, gated iterations, and measurement of the build itself. Numbers on this page are as recorded in each project's own repository, as of September 2026.

The method

The same six habits show up across the projects below. The matrix further down shows where each one is fully in place and where it isn't yet.

  1. CharterScope, gates, and rules before any code
  2. Spec and decisionsDated records; amend, don't delete
  3. Test firstRed spec, then green; green stays green
  4. Gated iterationsNothing significant ships without approval
  5. Measure the buildTests, time, and cost per step
  6. Record and hand offBuild logs and project memory

Observability Copilot

An AI reasoning layer over the team's Datadog stack, built by an AI coding agent under my direction. I wrote no code by hand. What it does →

Code coverage, as recorded in the test log

Dated decision records

  • Charter first. A kickoff document set the gates (Plan → Design → Roadmap → approval → iterations) and the rule "propose, don't silently decide."
  • Test-first under a written invariant: once a test is green it stays green. Specs are written red first; every step runs the full suite and logs passing over total.
  • Defects owned in writing. When a UI switch shipped broken because tests checked that it existed rather than that it worked, the log records the root cause and the three tests added so it can't recur.
  • The build is measured. A hook records every prompt cycle: 66 cycles and about 447M tokens over the build, about 97% of them cache reads.
  • Guardrails on the build: no new dependency, cost, or security change without approval; never switch to a pricier model silently; secrets only in a gitignored file; read-only data access.

Where the evidence lives: the kickoff charter, DECISIONS.md, BUILD-LOG.md, TESTING.md, and the build-telemetry module.

Enterprise Conduct pipeline explainer

An interactive isometric simulation of the surveillance pipeline, used with customers to size infrastructure from projected workloads. What it does →

0

Changed pixels while paused, across all 8 rebuilt machines

6

Architecture decisions on record, plus deliberate omissions

0

Runtime dependencies; no framework, no build step

  • A standing spec (about 800 lines) with a progress log and the rule "amend a decision rather than delete it."
  • A decision record with 6 architecture decisions, a work-item checklist (22 of 23 done), and a section on what was deliberately left out.
  • Specs before rework: a written rework spec with an acceptance checklist, merged through a pull request.
  • Checks at every step: syntax on every file; a headless smoke test that walks a message through every station and fails on any console error; an idle test that diffs frames while paused.
  • A five-tier fidelity boundary (computed, assumed, controlled, scaled, faked), kept identical in the code, the README, and the in-app About panel, so viewers know what to trust.

Where the evidence lives: the project spec, the floor-topology decision record, the rework spec, and the smoke-test script.

Personal project · September 2026

podcast-skills

An editorial production system for podcasts, built as Claude Code skills with an Editorial Board web app. It prepares a recording package (research, claim ledger, script, show notes, QA) for a person to approve; it doesn't generate audio.

248

Automated tests: 160 Python, 67 Vitest, 21 end-to-end

2

Operating systems in CI: Ubuntu and Windows

9

Pull requests delivering stages 0–7

  • Spec-first: a 1,337-line spec paired with a traceability document, and a 20-document roadmap with a Definition of Done.
  • Staged delivery: each stage on its own branch, merged by pull request; 39 commits in four days.
  • Tests that never call the real model: a deterministic fake Claude backs the suite, and CI runs it on two operating systems.
  • Rules for the agents: 10 hard rules, including "no fabricated precision" and "agents never set human review to approved," plus a hook that blocks writes outside allowed paths.
  • Real runs measured: about 69 seconds and US$0.25 for an intake run, and an explicit "not verified" note where a run wasn't checked.
